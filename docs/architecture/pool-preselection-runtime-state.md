# 号池预选运行时状态边界

## 目标

号池 provider 在候选预选阶段只代表“这个 provider、endpoint、model 组合可进入号池调度”，不能因为代表账号的熔断、健康分、RPM 或账号状态把整个号池提前跳过。

## 非目标

不改变普通非号池 key 的运行时跳过规则；不改变号池展开后的逐账号调度、冷却、额度耗尽、熔断和健康判断。

## 行为变化

预选阶段仍然检查 provider 级配额、用户/API Key 并发限制和静态可用性。若 provider 开启 `pool_advanced`，代表账号的账号级运行时状态不再用于跳过整池；后续由号池展开逻辑逐个账号判断可用性。

## 影响范围

影响本地执行调度中启用号池的 provider。非号池 provider 仍按单个 key 执行账号级运行时过滤。

## 验证方式

增加单元测试覆盖“号池代表账号熔断时，provider 仍进入候选列表”。同时保留既有非号池熔断跳过测试，确保普通 key 行为不变。
