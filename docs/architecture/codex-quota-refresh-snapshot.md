# Codex 配额刷新快照保护

## 目标

避免 Codex 管理页手动刷新配额时，把真实请求响应头里已经记录的 5H/周窗口覆盖成不完整数据。

## 非目标

不改变 Codex 账号授权、调度策略、计费口径和窗口用量统计方式。

## 行为变化

Codex `wham/usage` 刷新返回全 0 窗口时，不再把它当作有效限额窗口保存。付费账号只返回 `primary_window` 时，按 Codex 当前语义归为 5H 窗口；如果本次刷新缺少某个窗口，但旧快照里该窗口还没到恢复时间，则继续保留旧窗口。

## 影响范围

只影响 Codex provider key 的 `status_snapshot.quota.windows` 生成和展示。正常业务请求返回头仍会继续更新真实 5H/周窗口。

## 验证方式

运行 Codex 配额解析、管理刷新和号池快照相关测试，确认全 0 刷新不会删除 5H 窗口，单窗口 300 分钟不会误显示为周限额。
